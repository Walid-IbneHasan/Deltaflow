Status: done, 2026-10-18. The design argument is in
[`docs/delta-algebra.md`](../delta-algebra.md). The old-row decision is
[`docs/decisions/0003`](../decisions/0003-source-arrangements.md). Hypothesis

## What exists

| Module | Contents |
|---|---|
| `core/` | `Row` (immutable, hashable), `Multiset`, `Delta`, `consolidate`, `accumulate`, `Frontier` / `MutableFrontier` |
| `state/arrangement.py` | keyed copy of each source table: whole old rows, TOAST resolution, consistency checks |
| `operators/` | `Source`, `Filter`, `Map` |
| `planner/` | `Deltaflow().view(...).source(...).filter(...).map(...).select(...).sink(...)`, compiled to an operator graph |
| `sinks/memory.py` | `MemorySink`: result as of its frontier, raises on negative multiplicities |
| `runtime/` | `Engine` (transaction → deltas → views → frontier advance), source/publication validation, snapshot load, `Runner` |

```python
df = Deltaflow()
(
    df.view("big_open_orders")
    .source("public.orders")
    .filter(lambda r: r["amount"] >= 4000 and r["status"] != "cancelled")
    .select("id", "customer_id", "amount")
    .sink(sink := MemorySink())
)
async with Runner(df, dsn) as runner:
    await runner.run()  # sink.result is the view as of sink.frontier
```

## Acceptance

> Property tests (Hypothesis) for the algebra laws; a filtered view matches
> `SELECT ... WHERE` on random workloads.

**Algebra laws** (`tests/unit/core/test_algebra.py`, `tests/unit/operators/`):

- multisets form an abelian group;
- consolidation is canonical, idempotent, independent of arrival order,
  and can be done incrementally, with accumulation preserved at every
  frontier;
- accumulation is a homomorphism;
- the frontier meet is a semilattice, and completeness is monotone in the
  frontier;
- map and filter commute with + and negation, and incremental equals
  recompute at every frontier.

A soak at 2,000 examples per property passed (`HYPOTHESIS_PROFILE=thorough`,
21 core tests in 137 s).

**Arrangement and engine properties** (`tests/unit/state/`,
`tests/unit/runtime/`). Random change scripts, under default and FULL
identity and including unchanged-TOAST placeholders, PK changes, truncates
and changes to unrelated tables, are checked after every transaction:

- the accumulated deltas equal the model table;
- each view equals the model filtered or mapped in plain Python;
- each sink's frontier equals the transaction's `end_lsn`.

**Differential** (`tests/differential/test_filter_views.py`). Eight views,
each paired with its SQL:

- the identity view;
- filters with explicit NULL handling;
- non-injective projections, i.e. bags with multiplicities in the
  hundreds;
- md5 and length of every bio, which catches unresolved TOAST.

The phases:

1. Seed 200 customers and 1,000 orders.
2. Compare all eight views after the snapshot.
3. Run 1,000 workload transactions in lockstep, comparing all eight as
   multisets after *each* one, i.e. at every frontier. Rolled-back
   transactions are compared too.
4. Run a 600-transaction burst while the engine consumes concurrently, and
   compare at the end.

## Explicitly not done in M2

- **Persistent state.** Arrangements and sinks live in memory, and every
  start re-reads a snapshot through a temporary slot. Spilling and the KV
  backend are M3; durability and resume are M5.
- **Bounded memory.** Every source table is held in full in memory. This
  is the arrangement's cost (decision 0003); M3 bounds it.
- **Frontier advance while idle.** Frontiers move only when a transaction
  arrives. Correctness is unaffected; freshness reporting is M6.
- **Detecting non-deterministic filters.** Non-deterministic maps are
  caught (negative multiplicity); filters are not. See delta-algebra.md
  §5.
- **NaN values, arrays, json.** NaN never equals itself in Python, so its
  retraction fails loudly. Arrays and json load as `list`/`dict`, which are
  unhashable and rejected when the row is built.
- **Schema changes on a live source.** They raise `SchemaChangedError`;
  re-registering the views is the remedy.
- **Partitioned tables as sources.** Rejected at start.
- **Joins, aggregates, distinct.** M3/M4. The DSL has no methods for them
  yet, so they cannot be requested by accident.
